САЙТ КАФЕ «СХІДНИЙ КУТОЧОК» — ВЕРСИЯ С БАЗОЙ ДАННЫХ
====================================================

ЧТО УМЕЕТ САЙТ
--------------
Меню с фото и поиском (ищет по-украински, по-русски и по-английски),
онлайн-заказ, оценки блюд, галерея каруселью, отзывы с Google,
анкета в команду, два языка, кнопка «наверх».
Проверено на ширине от 320 пикселей.


ЧТО ИЗМЕНИЛОСЬ
--------------
Раньше сайт был одним файлом: чтобы поменять цену, надо было лезть
в HTML через «Блокнот». Теперь это приложение с базой данных.

Меню, цены, фотографии блюд, галерея и контакты лежат в базе.
Меняются через панель управления в браузере — без единой строчки кода.

Плата за это — сайт больше нельзя просто открыть двойным кликом.
Ему нужен работающий сервер.


ЧТО ВНУТРИ
----------
  server.js          — сервер (без единой сторонней библиотеки)
  lib/db.js          — база: таблицы, запросы, первое наполнение
  public/index.html  — витрина
  public/app.js      — рисует меню и галерею из базы
  public/admin.html  — панель управления
  public/img/        — фотографии (81 файл)
  data/seed.json     — меню для первого запуска
  data/kutochok.db   — сама база, появится при первом старте


ЧТО В БАЗЕ
----------
  categories   — 9 разделов меню, включая «Додатки»
  dishes       — 93 позиции: названия укр/англ, состав, вес, ЦЕНА, фото
  gallery      — фотографии галереи с подписями
  ratings      — оценки блюд от гостей
  orders       — онлайн-заказы
  applications — анкеты в команду
  settings     — телефон, адрес, график, кальян, вакансии, переключатели


ПОСЛЕ КАЖДОГО ОБНОВЛЕНИЯ ФАЙЛОВ
-------------------------------
1. Закройте чёрное окно и запустите заново: node server.js
   (перезапуск нужен, если менялись server.js или lib/)
2. В браузере один раз нажмите Ctrl+F5 — это сбросит старую
   версию страницы, если она где-то залипла.

Начиная с этой версии сервер сам просит браузер проверять
свежесть страницы и скриптов, так что залипать больше не должно.


ФАЙЛ .env (ТОКЕН И ПАРОЛЬ)
-------------------------
В архиве файла .env НЕТ — это сделано специально. Если распаковать
архив поверх рабочей папки, ваши настоящие токен и пароль остались бы
на месте, а не затёрлись старыми значениями.

Если у вас уже есть рабочая папка — ничего не делайте, ваш .env
в ней остаётся как был.

Если начинаете с чистого листа:
1. Откройте файл .env.example в «Блокноте».
2. Впишите TG_TOKEN, TG_CHAT и ADMIN_PASSWORD.
3. Файл -> Сохранить как -> имя  .env  (с точкой в начале),
   «Тип файла» поставьте «Все файлы», кодировка UTF-8.
4. Положите его рядом с server.js.


ЗАПУСК НА СВОЁМ КОМПЬЮТЕРЕ (проверить, как работает)
-----------------------------------------------------
1. Поставьте Node.js версии 22 или новее: nodejs.org
2. Откройте папку в терминале и выполните:

     node server.js

3. Пароль админки берётся из строки ADMIN_PASSWORD в файле .env.
   Это значение ГЛАВНОЕ: поменяли в файле, перезапустили сервер —
   пароль сменился. Меню, фото и заказы при этом не теряются.

   Если строка ADMIN_PASSWORD пустая, при первом запуске пароль
   придумается сам и напечатается в чёрном окне один раз.

   ЗАБЫЛИ ПАРОЛЬ? Впишите новый в .env и перезапустите сервер.
   Удалять базу не нужно.

4. Витрина  — http://localhost:3000
   Панель   — http://localhost:3000/admin

Установка библиотек не нужна: зависимостей нет вообще.


РАЗМЕЩЕНИЕ В ИНТЕРНЕТЕ
----------------------
Нужен хостинг, который умеет запускать Node.js. Статический хостинг
(Netlify Drop, куда мы кидали прошлую версию) для этого НЕ подойдёт.

Render.com — рабочий вариант, порядка 7 долларов в месяц за сервис
с постоянным диском:

1. Загрузите папку в репозиторий на GitHub.
2. На Render: New -> Web Service -> подключите репозиторий.
   Build Command:  (оставить пустым)
   Start Command:  node server.js
3. Add Disk: имя data, путь /var/data, размер 1 ГБ.
4. Environment -> добавьте переменные:
     ADMIN_PASSWORD = ваш пароль
     DB_FILE        = /var/data/kutochok.db
     UPLOAD_DIR     = /var/data/uploads
5. Свой домен подключается в Settings -> Custom Domain.

Похоже настраиваются Railway.app и Fly.io.

!!! ВАЖНО. Пункты 3 и 4 пропускать нельзя. Без постоянного диска
    база и все загруженные фото сотрутся при каждом обновлении сайта,
    и меню откатится к исходному.


ПАНЕЛЬ УПРАВЛЕНИЯ
-----------------
Адрес: ваш-сайт/admin

  Страви              — цена, название укр/англ, состав, вес, фото,
                        раздел. Кнопка «Сховати» убирает блюдо с сайта,
                        не удаляя его.
  Категорії           — разделы меню и порядок.
  Заявки й замовлення — сюда падают онлайн-заказы, анкеты в команду
                        и сводка оценок блюд (внизу списка — те,
                        что гости оценивают хуже всего).
  Галерея             — загрузка фото, подписи, порядок.
  Контакти            — телефон, адрес, график, кальян, вакансии,
                        а также два переключателя:
                          show_ratings   1 = оценки видны гостям, 0 = нет
                          orders_enabled 1 = онлайн-заказ работает, 0 = выключен
  Пароль              — смена пароля входа.


ОНЛАЙН-ЗАКАЗ И TELEGRAM
-----------------------
Гость набирает корзину, оставляет имя и телефон. Заказ ложится
в таблицу orders, показывается в админке И уходит в Telegram.

Туда же уходят анкеты в команду (отключается настройкой
tg_applications = 0).

ГДЕ ЛЕЖИТ ТОКЕН
Файл .env в корне проекта:

  TG_TOKEN=токен от @BotFather
  TG_CHAT=id чата

Файл добавлен в .gitignore и на GitHub не попадёт. На хостинге
те же переменные задаются в разделе Environment, файл туда
класть не нужно.

ВАЖНО: токен работает только на сервере. В браузер он не попадает
никогда — проверено. Если положить его в JavaScript страницы,
любой посетитель сможет забрать бота себе.

ЕСЛИ TELEGRAM НЕДОСТУПЕН
Заказ всё равно сохраняется, и гость видит подтверждение. Терять
заказ из-за чужого сбоя нельзя. В админке такой заказ помечается
«не доставлено», рядом кнопка «Надіслати в Telegram» — отправит
повторно, когда связь восстановится.

ПРОВЕРКА СВЯЗИ
Админка -> Контакти -> кнопка «Перевірити звʼязок з Telegram».
Придёт тестовое сообщение в чат.

ФАЙЛЫ, КОТОРЫЕ ЗА ЭТО ОТВЕЧАЮТ
  lib/telegram.js — сборка текста сообщения и отправка
  lib/env.js      — чтение .env
  server.js       — вызовы в обработчиках /api/order и /api/apply


ОЦЕНКИ БЛЮД
-----------
Гость открывает блюдо и ставит от 1 до 5 звёзд. Один голос на блюдо
с устройства, переголосовать можно.

На сайте средняя оценка появляется только после трёх голосов —
чтобы одна случайная звезда не портила картину. В админке вы видите
все оценки сразу, отсортированные снизу вверх.

Если оценки показывать не хотите — поставьте show_ratings в 0.
Гости продолжат голосовать, но цифры увидите только вы.

Правки видны на сайте сразу после сохранения, перезапуск не нужен.

Фото при загрузке принимаются только настоящие (jpg, png, webp)
и не больше 8 МБ. Лучше заранее уменьшать снимки до ~1500 пикселей
по длинной стороне, иначе страница будет грузиться медленно.


РЕЗЕРВНАЯ КОПИЯ
---------------
Вся база — один файл kutochok.db. Копируйте его раз в неделю
(с диска хостинга или из папки data/). Этого достаточно,
чтобы восстановить меню целиком.


БЕЗОПАСНОСТЬ
------------
— пароль хранится хэшем (scrypt), не текстом;
— вход защищён от перебора: 8 попыток за 15 минут;
— сессия живёт неделю, cookie подписана и недоступна скриптам;
— запросы к базе параметризованы, подстановка SQL невозможна;
— загрузки проверяются по сигнатуре файла, а не по расширению.

Смените пароль сразу после установки и не используйте тот,
что показался в консоли при первом запуске.
